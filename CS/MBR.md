# MBR (Memory Buffer Register)

## 핵심 개념

- **메모리 버퍼 레지스터(Memory Buffer Register)**: 메모리에서 읽어온 데이터 또는 메모리에 쓸 데이터를 임시로 저장하는 레지스터
- **MDR(Memory Data Register)** 이라고도 불림
- CPU와 메모리 사이의 데이터 버스(Data Bus)와 연결됨
- MAR이 "어디서" 읽을지 저장한다면, MBR은 "무엇을" 읽었는지 저장

## MAR과 MBR의 역할 비교

```
MAR ── 주소 버스(Address Bus) ──▶ 메모리
MBR ◀─ 데이터 버스(Data Bus)  ── 메모리
```

| 레지스터 | 저장 내용          | 연결 버스   |
| -------- | ------------------ | ----------- |
| MAR      | 접근할 메모리 주소 | 주소 버스   |
| MBR      | 읽어온/쓸 데이터   | 데이터 버스 |

## 동작 흐름

```
읽기 (메모리 → CPU)
① MAR ← 읽을 주소
② 메모리[MAR 주소] → MBR로 데이터 전송
③ MBR → GPR/AC 등 레지스터로 이동 후 연산

쓰기 (CPU → 메모리)
① MAR ← 쓸 주소
② MBR ← 쓸 데이터
③ MBR의 데이터 → 메모리[MAR 주소]에 저장
```

## 버퍼로서의 역할

CPU와 메모리의 속도 차이를 완충

```
CPU 처리 속도 >> 메모리 접근 속도

MBR이 없다면 → CPU가 메모리 응답 올 때까지 직접 기다려야 함
MBR이 있다면 → MBR에 데이터 올라오면 CPU가 바로 가져감
```

## 게임 개발 관점에서

- 직접 다룰 일 없음
- **캐시 미스(Cache Miss)**: 필요한 데이터가 캐시에 없으면 RAM에서 MBR을 거쳐 CPU로 올라오는 과정이 발생 → 수백 사이클 지연. 게임 최적화에서 캐시 친화적 데이터 구조(배열 우선, 연속 메모리)를 선호하는 이유
- **Unity DOTS/ECS**: 데이터를 연속된 메모리에 배치해 MBR을 통한 메모리 접근 횟수를 최소화하는 설계

## 의문점 / 더 알아볼 것

- L1/L2 캐시가 MBR과 RAM 사이에서 어떻게 동작하는지
- DMA(Direct Memory Access) — CPU/MBR을 거치지 않고 메모리에 직접 접근하는 방식
