# 시스템 버스 (System Bus)

## 핵심 개념

- **시스템 버스**: CPU, 메모리, I/O 장치 간에 데이터를 주고받는 통신 경로
- 하드웨어 장치들을 연결하는 "고속도로"
- 세 종류의 버스로 구성됨

## 구성 요소

```
CPU ──────────────────────────── RAM
 │         시스템 버스            │
 ├── 주소 버스 (Address Bus) ────▶│  어디서 읽을지 주소 전달 (단방향)
 │                                │
 ├── 데이터 버스 (Data Bus)  ◀───▶│  실제 데이터 전송 (양방향)
 │                                │
 └── 제어 버스 (Control Bus) ────▶│  읽기/쓰기 신호 전달 (양방향)
```

| 버스        | 방향                | 역할                                                                         |
| ----------- | ------------------- | ---------------------------------------------------------------------------- |
| 주소 버스   | 단방향 (CPU → 장치) | 접근할 메모리 주소 전달. 비트 수가 주소 공간 한계 결정                       |
| 데이터 버스 | 양방향              | 실제 데이터(명령어, 값) 전송. 비트 수가 한 번에 전송 가능한 데이터 크기 결정 |
| 제어 버스   | 양방향              | 읽기/쓰기 구분, 인터럽트 신호, 클럭 신호 등 제어 신호 전달                   |

## 버스 폭과 성능

```
주소 버스 32bit → 2³² = 4GB 주소 공간 한계 (32bit OS 메모리 한계의 이유)
주소 버스 64bit → 2⁶⁴ = 이론상 16EB

데이터 버스 8bit  → 한 번에 1바이트 전송
데이터 버스 64bit → 한 번에 8바이트 전송 → 버스 대역폭 향상
```

## PCIe — 확장 버스

GPU, SSD 등 고속 장치를 연결하는 버스

```
CPU ── PCIe 버스 ── GPU (그래픽 카드)
                 ── NVMe SSD
                 ── 네트워크 카드
```

- 레인(Lane) 수가 많을수록 대역폭 증가 (x1, x4, x8, x16)
- GPU는 보통 PCIe x16 슬롯 사용

## 게임 개발 관점에서

- **CPU-GPU 병목**: CPU와 GPU가 PCIe 버스로 연결되어 있어 데이터 전송량이 많아지면 병목 발생. 텍스처나 메시 데이터를 매 프레임 CPU에서 GPU로 넘기지 않고 VRAM에 미리 올려두는 이유
- **Draw Call 비용**: CPU가 GPU에 렌더링 명령을 보낼 때 제어 버스와 데이터 버스를 사용. Draw Call이 많아질수록 버스 통신 횟수 증가 → 배칭(Batching)으로 최소화
- **NVMe SSD**: PCIe 버스를 직접 사용하는 SSD. 기존 SATA SSD보다 대역폭이 훨씬 높아 게임 로딩 속도 향상에 직결

## 의문점 / 더 알아볼 것

- USB, SATA도 버스의 일종 — 각각의 대역폭 비교
- Apple Silicon의 통합 메모리(Unified Memory)가 CPU-GPU 간 버스 병목을 줄이는 원리
