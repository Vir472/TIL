# 보수기 (Complementer)

## 핵심 개념

- **보수기(Complementer)**: 피연산자를 **2의 보수**로 변환하는 회로
- 뺄셈을 덧셈으로 바꾸기 위한 장치 — 별도의 뺄셈 회로 없이 가산기만으로 뺄셈 처리 가능하게 함
- 하드웨어를 단순하게 유지하면서 다양한 연산을 구현하는 핵심 아이디어

## 보수(Complement)란

```
1의 보수 — 모든 비트를 반전
  6  = 0000 0110
  ~6 = 1111 1001  (1의 보수)

2의 보수 — 1의 보수에 1을 더함
  ~6 + 1 = 1111 1010  (2의 보수 = -6)
```

2의 보수는 컴퓨터에서 음수를 표현하는 방식

## 보수기가 뺄셈을 가능하게 하는 원리

```
A - B = A + (-B) = A + (B의 2의 보수)

10 - 6 계산
① 보수기: 6(0000 0110) → 2의 보수 → -6(1111 1010)
② 가산기: 10 + (-6)
   0000 1010
+  1111 1010
────────────
   0000 0100  (= 4)  ← 올림 발생하지만 무시
```

가산기 하나로 덧셈과 뺄셈 모두 처리 가능

## 하드웨어 구현

```
보수기 동작 (2의 보수 변환)
① XOR 게이트로 모든 비트 반전 (1의 보수)
② 가산기로 1을 더함 (2의 보수 완성)

매우 단순한 회로로 구현 가능
```

## 게임 개발 관점에서

- 직접 다룰 일 없음
- **음수 표현 이해**: C#의 `int`가 -2,147,483,648 ~ 2,147,483,647 범위인 이유가 2의 보수 표현 방식 때문. 최상위 비트가 부호 비트로 사용됨
- **비트 반전 연산**: C#의 `~` 연산자가 1의 보수를 만드는 연산. `~x + 1`이 `-x`가 되는 것이 보수기 원리와 동일

```csharp
  int x = 6;
  int negX = ~x + 1;  // -6 (2의 보수)
  // ~x + 1 == -x 는 항상 성립
```

- **림버스컴퍼니 프로젝트**: 정신력 감소(뺄셈)가 내부적으로 보수기를 통해 덧셈으로 처리됨

## 의문점 / 더 알아볼 것

- 1의 보수 방식으로 음수를 표현했던 초기 컴퓨터의 문제점 (0이 두 개: +0, -0)
- 부동소수점에서 음수를 표현하는 방식이 2의 보수와 다른 이유 (부호 비트 방식)
