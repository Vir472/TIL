# 비트와 바이트 (Bit & Byte)

## 핵심 개념

- **비트(Bit)**: 0 또는 1 하나. 컴퓨터가 다루는 정보의 **가장 작은 단위**
- **바이트(Byte)**: 비트 8개 묶음. 메모리에서 **주소를 붙이는 가장 작은 단위**
- 메모리는 비트 하나하나가 아니라 바이트 단위로 번지가 매겨짐. 그래서 `bool`도 실제로는 1바이트를 차지함

```
1 바이트 = 8 비트

비트 위치   7   6   5   4   3   2   1   0
값          0   1   0   0   0   0   0   1    = 65 ('A')
           └── 상위 니블 ──┘ └── 하위 니블 ──┘
```

## 표현할 수 있는 개수

- n비트로 표현할 수 있는 경우의 수는 **2ⁿ개**

| 비트 수 | 경우의 수 | 예 |
| --- | --- | --- |
| 1 | 2 | 켜짐/꺼짐 |
| 4 (니블) | 16 | 16진수 한 자리 |
| 8 (1바이트) | 256 | `byte` (0~255) |
| 16 | 65,536 | `ushort` |
| 32 | 약 43억 | `int`, `uint` |
| 64 | 약 1844경 | `long`, `ulong` |

## 16진수와의 관계

- 4비트는 16진수 한 자리와 정확히 대응함
- 그래서 **1바이트 = 16진수 두 자리**임. `0xFF` = 255 = `1111 1111`
- 메모리 덤프, 색상 코드(`#FF8800`), 해시값을 16진수로 쓰는 이유가 이것임. 바이트 경계가 눈에 바로 보임

## 크기 단위

| 표기 | 기준 | 값 |
| --- | --- | --- |
| KB (킬로바이트) | 10진 | 1,000 바이트 |
| KiB (키비바이트) | 2진 | 1,024 바이트 |
| MB / MiB | | 1,000² / 1,024² |
| GB / GiB | | 1,000³ / 1,024³ |

- 저장장치 제조사는 10진(KB), OS는 2진(KiB)을 쓰는 경우가 많음
- 1TB 디스크가 OS에서 약 931GB로 보이는 이유가 이 차이임

## 바이트 순서 (Endianness)

- 여러 바이트로 이루어진 값을 메모리에 **어느 쪽부터 저장하는가**의 문제

```
값 0x12345678 (4바이트 int)

리틀 엔디언   78 56 34 12    ← 작은 자리부터 (x86, 대부분의 ARM)
빅 엔디언     12 34 56 78    ← 큰 자리부터 (네트워크 표준)
```

- 같은 기기 안에서는 신경 쓸 일이 없음
- 바이트를 **파일이나 네트워크로 주고받을 때** 양쪽 순서가 다르면 값이 엉뚱하게 읽힘

## 게임 개발 관점에서

**메모리 계산의 기본 단위**

- 텍스처 메모리는 `가로 × 세로 × 픽셀당 바이트`로 계산함. [[Texture]] 참고
- 데이터 타입을 고를 때도 "몇 바이트짜리를 몇 개 가지는가"로 메모리를 어림함

**비트 단위로 정보를 압축함**

- `bool` 여러 개는 각각 1바이트를 쓰지만, 비트 하나씩 쓰면 1바이트에 8개를 담을 수 있음
- [[LayerMask]], [[Flags Enum]]이 이 방식임

**네트워크와 세이브 파일**

- 패킷 크기를 줄이려고 값의 범위에 맞춰 바이트 수를 최소화함. 0~100인 체력을 `int`(4바이트) 대신 `byte`(1바이트)로 보내는 식
- 바이너리 세이브 파일이나 패킷은 엔디언을 맞춰야 다른 기기에서도 같은 값으로 읽힘

## 의문점 / 더 알아볼 것

- 워드(Word) — CPU가 한 번에 처리하는 데이터 크기와 32비트·64비트 아키텍처
- 메모리 정렬(Alignment) — 구조체 크기가 필드 합보다 커지는 이유
- 음수를 비트로 표현하는 방법 — [[Complementer]], 2의 보수
- C#의 `BitConverter`와 엔디언 확인 방법
- 비트 연산자(`&`, `|`, `^`, `~`, `<<`, `>>`) 정리
