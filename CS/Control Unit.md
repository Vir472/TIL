# 제어장치 (CU, Control Unit)

## 핵심 개념

- **제어장치(Control Unit)**: CPU 안에서 명령어를 해석하고 다른 장치에 제어 신호를 보내는 "지휘자" 역할
- 직접 연산을 수행하지 않음 — 연산은 ALU가 담당
- 모든 명령어 실행 흐름을 조율하는 핵심 장치

## 역할

```
① IR에서 명령어를 가져옴
② 명령어의 Opcode를 해석 (무엇을 해야 하는가)
③ 각 장치에 제어 신호 전달
   ├─ ALU에게 → "덧셈 해"
   ├─ 레지스터에게 → "이 값 저장해"
   ├─ 메모리에게 → "이 주소에서 읽어와"
   └─ PC에게 → "다음 주소로 이동해"
④ 실행 결과를 바탕으로 다음 명령어 사이클 시작
```

## 하드와이어드 vs 마이크로프로그램 방식

```
하드와이어드 방식 (RISC — ARM, MIPS)
  제어 신호를 하드웨어 회로로 직접 구현
  → 빠름, 단순한 명령어 세트에 적합
  → 모바일(ARM)에서 사용

마이크로프로그램 방식 (CISC — x86)
  복잡한 명령어를 더 작은 마이크로 명령어로 분해해서 실행
  → 유연하고 복잡한 명령어 처리 가능
  → PC/서버(Intel, AMD)에서 사용
```

## 게임 개발 관점에서

- 직접 다룰 일 없음
- **RISC vs CISC와 게임 플랫폼**: PC(x86, CISC)와 모바일(ARM, RISC)의 제어장치 설계 차이가 동일한 게임 코드라도 플랫폼별 최적화가 필요한 이유 중 하나
- **파이프라인**: 현대 제어장치는 여러 명령어를 동시에 처리하는 파이프라인을 지원. 제어장치가 Fetch/Decode/Execute를 겹쳐서 처리 → 성능 향상

## 의문점 / 더 알아볼 것

- 파이프라인 해저드(Pipeline Hazard) — 제어장치가 명령어를 겹쳐 처리할 때 생기는 충돌
- 분기 예측(Branch Prediction) — 제어장치가 if/else 분기를 미리 예측해 실행하는 기법
