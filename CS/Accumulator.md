# 누산기 (Accumulator)

## 핵심 개념

- **누산기(Accumulator)**: ALU의 연산 결과를 저장하고 다음 연산의 입력으로 재사용하는 레지스터
- 하드웨어적으로는 레지스터이지만 CPU 구조에서 ALU와 긴밀하게 연결된 장치로 분류됨
- "누산(累算)" — 연산 결과를 **누적**해서 쌓는다는 의미

## ALU와 누산기의 관계

```
     피연산자1 ──┐
                 ├──▶ ALU (연산 수행) ──▶ 누산기(AC) ──┐
     피연산자2 ──┘                                      │
                                                        │ 다음 연산의
          ┌─────────────────────────────────────────────┘ 입력으로 재사용
          ▼
         ALU
```

ALU의 출력이 바로 AC로 들어가고, AC의 값이 다시 ALU의 입력이 될 수 있는 피드백 구조

## 누적 연산 예시

```
데미지 합산 계산
AC = 0
AC = AC + 50   → AC = 50   (기본 데미지)
AC = AC + 20   → AC = 70   (추가 데미지)
AC = AC - 10   → AC = 60   (방어력 차감)
AC = AC * 2    → AC = 120  (치명타 배율)

최종 데미지 = 120
```

각 단계의 결과가 AC에 누적되면서 최종 값이 만들어짐

## 초기 CPU vs 현대 CPU

```
초기 단순 CPU
  AC가 유일한 연산 결과 저장소
  모든 연산이 반드시 AC를 거침
  → 구조 단순, 프로그래밍 제약 많음

현대 CPU (x86-64, ARM64)
  GPR이 많아져서 어느 레지스터나 연산 결과 저장 가능
  AC의 특수 지위가 약해짐
  x86에서는 RAX가 관례적으로 AC 역할
```

## 게임 개발 관점에서

- 직접 다룰 일 없음
- **누적 연산 최적화**: 게임에서 여러 수치를 합산하는 계산(총 데미지, 스탯 합계)이 내부적으로 AC를 재사용하는 방식으로 처리됨 — 매번 메모리에 쓰지 않고 레지스터 안에서 누적

## 의문점 / 더 알아볼 것

- RISC 아키텍처(ARM)에서 누산기 개념이 어떻게 변화했는지
- FMA(Fused Multiply-Add) — 곱셈과 덧셈을 누산기에서 한 번에 처리하는 명령어
