#IR (Instruction Register)

## 핵심 개념

- **명령어 레지스터(Instruction Register)**: 현재 실행 중인 명령어를 저장하는 레지스터
- CPU가 메모리에서 명령어를 가져오면(Fetch) 실행 전에 IR에 저장됨
- 제어장치(CU)가 IR의 내용을 해석해서 어떤 연산을 할지 결정

## 동작 흐름

```
① PC가 가리키는 메모리 주소에서 명령어를 가져옴 (Fetch)
② 가져온 명령어 → IR에 저장
③ 제어장치가 IR의 명령어를 해석 (Decode)
④ 해석 결과에 따라 ALU, 레지스터 등에 제어 신호 전달 (Execute)
⑤ PC를 다음 명령어 주소로 증가
⑥ 반복
```

## PC와의 관계

```
PC → 다음 실행할 명령어의 주소
IR → 지금 실행 중인 명령어의 내용

PC가 주소를 가리키면, 그 주소의 명령어가 IR로 옮겨짐
```

## 명령어 구조

IR에 저장되는 명령어는 보통 두 부분으로 구성됨

```
┌──────────────┬──────────────────┐
│  연산 코드   │    피연산자      │
│  (Opcode)    │   (Operand)      │
│  무엇을 할지 │  어떤 데이터로   │
└──────────────┴──────────────────┘

예) ADD R1, R2
    Opcode   = ADD (더하기)
    Operand  = R1, R2 (더할 대상)
```

## 게임 개발 관점에서

- 직접 다룰 일 없음 — 컴파일러가 C# 코드를 기계어 명령어로 변환하고 CPU가 IR에 자동으로 적재
- **디버거와 IR**: 중단점에서 실행이 멈췄을 때 CPU는 해당 명령어를 IR에 올려둔 상태로 대기
- **Unity IL2CPP**: C# → IL → C++ → 기계어 순으로 변환된 최종 명령어가 런타임에 IR로 올라와 실행됨

## 의문점 / 더 알아볼 것

- 파이프라인 CPU에서 IR이 여러 단계에 걸쳐 사용되는 방식
- RISC vs CISC 아키텍처에서 명령어 길이와 IR 크기의 차이
