# MAR (Memory Address Register)

## 핵심 개념

- **메모리 주소 레지스터(Memory Address Register)**: CPU가 메모리에 접근할 때 사용할 주소를 저장하는 레지스터
- RAM에 읽기/쓰기 요청 전에 반드시 MAR에 주소를 먼저 담아야 함
- CPU와 메모리 사이의 주소 버스(Address Bus)와 연결됨

## 동작 흐름

```
메모리 읽기
① CPU가 읽고 싶은 주소(0x00A0)를 MAR에 저장
② MAR → 주소 버스를 통해 메모리에 주소 전달
③ 메모리가 해당 주소의 데이터를 MBR로 전송
④ CPU가 MBR에서 데이터를 가져와 연산

메모리 쓰기
① CPU가 쓸 주소(0x00A0)를 MAR에 저장
② 쓸 데이터를 MBR에 저장
③ MAR + MBR → 메모리에 전달 → 해당 주소에 데이터 저장
```

## MAR의 크기와 메모리 한계

```
MAR 크기 = 32bit → 최대 2³² = 4GB 주소 공간 (32bit OS의 메모리 한계)
MAR 크기 = 64bit → 최대 2⁶⁴ = 이론상 16EB (64bit OS)
```

32bit 시스템에서 RAM이 4GB를 넘길 수 없었던 이유가 MAR 크기 때문

## 게임 개발 관점에서

- 직접 다룰 일 없음 — 모든 메모리 접근은 OS와 컴파일러가 처리
- **32bit vs 64bit 게임**: 32bit 빌드는 MAR 크기 제한으로 4GB 이상 RAM 활용 불가. 대형 오픈월드 게임이 64bit 빌드를 요구하는 이유
- **Unity 빌드 타겟**: Unity에서 PC 빌드 시 64bit(x86_64) 선택이 기본값인 이유와 연결됨

## 의문점 / 더 알아볼 것

- 가상 메모리(Virtual Memory)에서 MAR의 주소가 물리 주소로 변환되는 과정 (MMU)
- 캐시 메모리 접근 시에도 MAR을 거치는지
