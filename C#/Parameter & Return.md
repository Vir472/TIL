# 매개변수와 반환값 (Parameter & Return)

## 핵심 개념

- **매개변수(Parameter)**: 메서드가 **받을 값의 자리**. 선언할 때 정함
- **인수(Argument)**: 호출할 때 그 자리에 **실제로 넣는 값**
- **반환값(Return Value)**: 메서드가 일을 마치고 **호출한 쪽으로 돌려주는 값**
- 메서드는 "매개변수로 받고, 반환값으로 돌려준다"가 기본 흐름임

```mermaid
graph LR
    A["호출하는 쪽"] -->|인수 전달| B["메서드<br/>매개변수로 받음"]
    B -->|반환값| A
```

## 값이 전달되는 방식

- C#은 기본적으로 **값으로 전달(Pass by Value)**함. 인수의 **복사본**이 매개변수에 들어감
- 그런데 무엇이 복사되는지가 타입마다 다름

| 인수의 타입 | 복사되는 것 | 메서드 안에서 바꾸면 |
| --- | --- | --- |
| 값 타입 (`int`, `struct`) | 값 전체 | **원본은 그대로** |
| 참조 타입 (`class`, 배열) | **참조(주소)** | 객체 내용을 바꾸면 원본에 반영됨 |

- 참조 타입을 넘기면 "원본이 넘어간다"고 오해하기 쉬움. 실제로는 **같은 객체를 가리키는 주소의 복사본**이 넘어감
- 그래서 메서드 안에서 객체의 필드를 바꾸면 원본도 바뀌지만, 매개변수에 **새 객체를 대입**하면 원본 변수는 그대로임
- 원본 변수 자체를 바꾸고 싶다면 `ref`, `out` 같은 한정자가 필요함. [[Parameter modifier]] 참고
- 값 타입과 참조 타입의 차이는 [[Value & Reference]] 참고

## 매개변수 관련 문법

| 문법 | 의미 |
| --- | --- |
| 선택적 매개변수 | 기본값을 지정해 두면 호출할 때 생략할 수 있음 |
| 명명된 인수 | 매개변수 이름을 붙여 순서와 관계없이 전달함 |
| `params` | 개수가 정해지지 않은 인수를 배열로 받음 |
| `ref`, `out`, `in` | 복사 대신 원본을 참조로 전달함 |

**선택적 매개변수 주의**

- 기본값은 **호출하는 쪽 코드에 박혀 컴파일됨**
- 나중에 기본값을 바꿔도, 그 메서드를 부르는 다른 어셈블리는 다시 컴파일하기 전까지 옛 값을 씀

**명명된 인수가 유용한 경우**

- `bool` 인수를 여러 개 넘기면 호출부만 봐서는 각각이 무슨 뜻인지 알 수 없음
- 이름을 붙여 넘기면 호출하는 코드만으로 의도가 드러남

## 반환값

| 형태 | 의미 |
| --- | --- |
| `void` | 돌려주는 값 없음. 일만 하고 끝남 |
| 단일 값 | 타입 하나를 돌려줌 |
| 여러 값 | 튜플, `out` 매개변수, 구조체·클래스로 묶어서 돌려줌 |

**`return`의 두 역할**

- 값을 돌려주는 것과 동시에 **그 자리에서 메서드를 끝냄**
- 조건이 맞지 않으면 일찍 빠져나가는 방식(Early Return)으로 쓰면 중첩된 `if`가 줄어 읽기 쉬워짐

**여러 값을 돌려주는 방법 비교**

| 방법 | 장점 | 단점 |
| --- | --- | --- |
| 튜플 | 간단함. 이름도 붙일 수 있음 | 여러 곳에서 쓰이면 의미가 흐려짐 |
| `out` 매개변수 | 성공 여부와 결과를 함께 줄 때 관례적임 | 여러 개가 되면 호출부가 지저분해짐 |
| 구조체·클래스 | 의미가 명확하고 재사용됨 | 타입을 따로 만들어야 함 |

## Try 패턴

- "실패할 수도 있는 조회"는 **성공 여부를 `bool`로 반환하고, 결과는 `out`으로** 주는 관례가 있음
- `TryGetValue`, `TryParse`, 유니티의 `TryGetComponent`가 이 형태임
- `null`을 반환하는 방식보다 **실패 처리를 빠뜨리기 어려움**. 호출부가 성공 여부를 자연스럽게 확인하게 됨

## 오버로딩과 시그니처

- 같은 이름의 메서드를 **매개변수 구성만 다르게** 여러 개 만들 수 있음 (오버로딩)
- 구분 기준(시그니처)은 **이름 + 매개변수의 개수·타입·순서**임
- **반환 타입은 시그니처에 포함되지 않음**. 반환 타입만 다른 메서드는 만들 수 없음

## 게임 개발 관점에서

**반환값으로 받은 구조체는 복사본임**

- 구조체를 반환하는 메서드나 프로퍼티의 결과를 바로 수정해도 원본은 바뀌지 않음
- 유니티에서 위치의 x만 바꾸려다 컴파일 에러가 나는 이유가 이것임. [[Property]] 참고

**컬렉션을 반환하면 할당이 생김**

- 결과 목록을 새 배열이나 리스트로 만들어 반환하는 메서드는 호출할 때마다 힙에 할당함
- 매 프레임 쓰는 경우에는 **호출하는 쪽이 미리 만든 버퍼를 매개변수로 넘기고**, 메서드가 거기에 채우는 방식을 씀
- 유니티 물리 질의의 결과 버퍼 방식이 이 패턴임. [[Cast & Overlap]] 참고

**큰 구조체는 복사 비용이 있음**

- 값 타입은 넘길 때마다 전체가 복사됨. 필드가 많은 구조체를 자주 넘기면 비용이 쌓임
- 읽기만 할 거라면 `in`으로 복사 없이 넘길 수 있음

**매개변수가 많아지면 묶을 것**

- 매개변수가 대여섯 개를 넘으면 순서를 헷갈리기 쉽고, 하나 추가할 때마다 모든 호출부를 고쳐야 함
- 관련된 값들을 하나의 구조체로 묶어 넘기면 읽기 쉬워지고 변경에도 강해짐

## 의문점 / 더 알아볼 것

- `ref` 반환 — 값이 아니라 위치를 돌려주는 방법
- 튜플의 분해(Deconstruction)와 `_` 무시 변수
- 반환 타입으로 `IEnumerable`, `IReadOnlyList`, `List` 중 무엇을 고를지
- 반환값을 무시하면 안 되는 메서드를 표시하는 방법
- 공변 반환 타입 — 오버라이드할 때 더 구체적인 타입을 반환하기
