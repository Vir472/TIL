# 동적 할당과 힙 (Dynamic Allocation)

## 핵심 개념

- **동적 할당**: 실행 중에 필요한 만큼 메모리를 **힙(Heap)**에서 받아 쓰는 것
- 스택은 메서드가 끝나면 함께 사라지지만, 힙에 할당한 메모리는 **메서드와 무관하게 살아남음**
- 그래서 "언제까지 살아야 하는지 호출 구조로 정할 수 없는 데이터"는 힙에 둠
- 짝이 되는 개념은 [[Local Variable]] (스택), OS 관점의 영역은 [[Heap Segment]] 참고

## 메모리 할당 방식 비교

| 구분 | 정적 영역 | 스택 | 힙 |
| --- | --- | --- | --- |
| 할당 시점 | 프로그램 시작 | 메서드 호출 | `new` 할 때 |
| 해제 시점 | 프로그램 종료 | 메서드 종료 | **GC가 판단할 때** |
| 크기 | 컴파일 시 결정 | 작음 (보통 1MB 내외) | 큼 |
| 관리 비용 | 없음 | 거의 없음 | 있음 |
| C#에서 들어가는 것 | `static` 필드 | 지역 변수, 매개변수 | 객체, 배열, 문자열 |

## 수명

```mermaid
graph LR
    A["new로 힙에 객체 생성"] --> B["지역 변수나 필드가<br/>주소를 참조"]
    B --> C["참조가 모두 끊김"]
    C --> D["GC가 도달 불가로 판단"]
    D --> E["회수"]
```

- 객체의 수명은 **누가 참조하고 있는가**로 결정됨. 메서드가 끝났는지와는 무관함
- C/C++은 개발자가 직접 해제(`free`, `delete`)하지만, C#은 [[GC]]가 회수함
- 직접 해제할 필요가 없는 대신, **언제 회수될지 통제할 수 없음**

## 무엇이 힙에 가는가

| 대상 | 비고 |
| --- | --- |
| 클래스 인스턴스 | `new`로 만드는 모든 참조 타입 |
| **배열** | **값 타입 배열도 힙**임. `int[]`, `Vector3[]` 모두 해당 |
| 문자열 | 연결하거나 변환할 때마다 새 문자열이 생김 |
| 박싱된 값 | 값 타입을 `object`로 다룰 때. [[Boxing & Unboxing]] |
| 캡처된 지역 변수 | 람다가 캡처하면 숨은 클래스로 옮겨짐. [[Closure]] |
| 델리게이트 | 메서드를 델리게이트로 만들 때 |
| 이터레이터, async 상태 머신 | `yield`, `async` 메서드 호출 시 |

- "구조체는 스택"이라는 말은 **지역 변수일 때만** 맞음. 구조체 배열이나 클래스의 필드로 들어간 구조체는 힙에 있음

## 할당 비용과 회수 비용

- .NET은 힙 할당 자체가 빠름. 다음 빈자리로 포인터를 옮기기만 하는 경우가 많음
- 비싼 쪽은 **회수**임. 할당이 쌓이면 GC가 돌고, 그동안 프로그램이 멈춤
- 유니티의 GC는 세대 구분과 압축이 없어 할당이 많을수록 회수 비용과 단편화가 함께 커짐. 자세한 내용은 [[GC]] 참고

**단편화**

- 할당과 회수를 반복하면 힙에 작은 빈 공간들이 흩어짐
- 전체 여유 공간은 충분한데 연속된 큰 공간이 없어 힙을 새로 늘리게 됨
- 유니티에서는 한 번 늘어난 힙이 잘 줄어들지 않음

## 게임 개발 관점에서

**매 프레임 할당을 0에 가깝게**

- 프로파일러의 GC Alloc에서 매 프레임 숫자가 찍히는 코드가 GC 스파이크의 원인이 됨
- 대표적인 원인 — 매 프레임 `new List<>()`, 문자열 연결, LINQ, 캡처하는 람다, 배열을 반환하는 API

**할당을 줄이는 기본 방법**

| 방법 | 내용 |
| --- | --- |
| 재사용 | 컬렉션을 필드로 한 번 만들고 비워서 다시 씀 |
| 풀링 | 자주 생성·파괴되는 객체를 미리 만들어 돌려 씀. [[ObjectPooling]] |
| 캐싱 | 매번 새로 만드는 대신 결과를 저장해 둠 |
| 값 타입 활용 | 작고 짧게 쓰이는 데이터는 구조체로. [[Struct & Class]] |
| 미리 할당 | 로딩 시점에 필요한 만큼 한꺼번에 만들어 둠 |

**할당 시점을 옮기는 사고방식**

- 할당을 완전히 없애기보다 **끊겨도 티가 안 나는 시점**(로딩, 씬 전환)으로 몰아넣는 것이 현실적인 전략임
- 전투 중에는 새로 만들지 않고, 미리 만들어 둔 것을 꺼내 쓰는 구조를 지향함

## 의문점 / 더 알아볼 것

- C의 `malloc`/`free`, C++의 `new`/`delete`와 C#의 차이 — 해제 책임이 누구에게 있는가
- 큰 객체 힙(LOH) — 큰 배열이 별도로 관리되는 이유
- `ArrayPool<T>` — 배열을 빌려 쓰고 돌려주는 표준 풀
- `stackalloc`, `Span<T>` — 작은 배열을 힙 대신 스택에 두는 방법
- 메모리 할당자의 종류 — 프리 리스트, 버디 할당, 슬랩 할당
