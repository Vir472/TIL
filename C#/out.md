# out 매개변수 (Out Parameter)

## 핵심 개념

- **`out` 매개변수**: 메서드가 **결과를 돌려주기 위해** 쓰는 매개변수
- 일반 매개변수는 값을 **받는** 자리지만, `out`은 메서드가 호출한 쪽 변수에 **값을 직접 써 넣는** 자리임
- 반환값이 하나뿐인 한계를 넘어, 여러 결과를 돌려줄 때 씀
- 매개변수 한정자 전반은 [[Parameter modifier]], 일반적인 전달 방식은 [[Parameter & Return]] 참고

```mermaid
graph LR
    A["호출하는 쪽<br/>변수 준비 (초기화 불필요)"] -->|"변수의 위치를 넘김"| M["메서드"]
    M -->|"그 위치에 직접 값을 씀"| A
```

## 지켜야 할 규칙

| 규칙 | 이유 |
| --- | --- |
| 메서드 안에서 **반드시 값을 대입**해야 함 | 안 하면 컴파일 에러. 호출한 쪽은 값이 들어온다고 믿기 때문임 |
| 호출 전에 초기화할 **필요가 없음** | 어차피 메서드가 덮어씀 |
| 메서드 안에서 **대입 전에 읽을 수 없음** | 들어오는 값이 없다고 간주함 |
| 호출할 때도 `out`을 **붙여야** 함 | 호출부만 봐도 이 변수가 바뀐다는 것이 드러남 |

## ref, in과의 비교

| 구분 | `ref` | `out` | `in` |
| --- | --- | --- | --- |
| 방향 | 들어오고 나감 (양방향) | **나가기만 함** | 들어오기만 함 |
| 호출 전 초기화 | 필요 | 불필요 | 필요 |
| 메서드 안에서 대입 | 선택 | **필수** | 불가 (읽기 전용) |
| 주 용도 | 원본을 고쳐야 할 때 | 결과를 돌려줄 때 | 큰 구조체를 복사 없이 넘길 때 |

- 셋 다 **복사가 아니라 변수의 위치(참조)를 넘김**. 내부 동작은 같고 컴파일러가 검사하는 규칙만 다름

## 호출 문법

| 형태 | 의미 |
| --- | --- |
| `out result` | 미리 선언해 둔 변수로 받음 |
| `out var result` | 호출하면서 변수를 바로 선언함 (C# 7) |
| `out _` | 결과가 필요 없을 때 버림 |

- 호출하면서 선언하는 방식이 가장 흔함. 선언과 사용이 한곳에 모여 읽기 쉬움

## 주 용도 — Try 패턴

- **성공 여부는 `bool`로 반환하고, 결과는 `out`으로** 주는 형태가 표준 관례임
- 실패할 수 있는 조회를 예외나 `null` 없이 다룰 수 있음

| 메서드 | 실패하는 경우 |
| --- | --- |
| `Dictionary.TryGetValue` | 키가 없음 |
| `int.TryParse` | 문자열이 숫자가 아님 |
| `TryGetComponent` | 컴포넌트가 없음 |

- 호출부가 `if`로 성공 여부를 확인하는 구조가 되어 실패 처리를 빠뜨리기 어려움

## 쓸 수 없는 곳

- `async` 메서드의 매개변수로 쓸 수 없음. `await`로 멈췄다 재개되는 동안 변수의 위치가 유효하다는 보장이 없음
- `yield return`을 쓰는 이터레이터 메서드에서도 같은 이유로 쓸 수 없음
- 람다 안에서 바깥 메서드의 `out` 매개변수를 캡처할 수 없음. [[Closure]] 참고
- 프로퍼티는 `out` 인수로 넘길 수 없음. 프로퍼티는 메서드라 변수의 위치가 없음. [[Property]] 참고

## out 대신 튜플

- 성공 여부와 결과처럼 **관례가 정해진 경우**는 `out`이 자연스러움
- 단순히 여러 값을 돌려주는 경우라면 **튜플 반환**이 더 읽기 쉬운 경우가 많음
- `out`이 두세 개를 넘어가면 호출부가 지저분해지므로, 튜플이나 구조체로 묶는 것을 고려함

## 게임 개발 관점에서

**물리 질의 결과를 받을 때**

- 레이캐스트는 충돌 여부를 `bool`로 반환하고, 충돌 정보는 `out`으로 채워 줌. Try 패턴과 같은 구조임
- 충돌 정보는 구조체라, 반환값으로 받으면 복사가 일어나지만 `out`으로 받으면 호출한 쪽 변수에 바로 채워짐

**컴포넌트 확인**

- `TryGetComponent`는 컴포넌트가 없을 때 할당 없이 `false`를 돌려줌
- 에디터에서 `GetComponent`가 null을 반환할 때 생기는 추가 비용을 피할 수 있어, 존재 여부가 불확실할 때 권장됨

**딕셔너리 조회는 TryGetValue로**

- 키가 있는지 먼저 확인하고 다시 꺼내는 방식은 **조회를 두 번** 함
- `TryGetValue`는 한 번의 조회로 확인과 꺼내기를 동시에 함

## 의문점 / 더 알아볼 것

- `[NotNullWhen(true)]` 같은 어트리뷰트로 Try 패턴의 null 분석을 돕는 방법
- `ref` 반환과 `ref` 지역 변수
- 구조체를 `out`으로 넘길 때와 반환할 때의 실제 성능 차이
- 튜플의 분해(Deconstruction)와 `out`의 관계 — 분해는 내부적으로 `out`을 씀
