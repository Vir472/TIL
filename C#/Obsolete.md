# Obsolete 어트리뷰트 (Obsolete)

## 핵심 개념

- **`Obsolete`**: "이 코드는 더 이상 쓰지 않는 것을 권한다"고 표시하는 [[Attribute]]
- 컴파일러가 이 표시를 읽고, 그 코드를 **사용하는 곳**에 경고나 에러를 띄움
- 코드를 바로 지우지 않고 **단계적으로 퇴출**시키기 위한 도구임

## 왜 바로 지우지 않는가

- 메서드를 바로 지우면, 그 메서드를 쓰던 모든 곳이 한꺼번에 컴파일 에러가 남
- 쓰는 곳이 많거나 다른 사람·다른 프로젝트의 코드라면 한 번에 고칠 수 없음
- `Obsolete`로 먼저 표시해 두면, 기존 코드는 계속 동작하면서 **경고로 대안을 안내**할 수 있음

```mermaid
graph LR
    A["1단계<br/>Obsolete 표시<br/>경고만"] --> B["2단계<br/>에러로 격상<br/>새로 쓰는 것 차단"]
    B --> C["3단계<br/>코드 삭제"]
```

## 인자

| 인자 | 의미 |
| --- | --- |
| 없음 | 기본 경고만 띄움 |
| 메시지 | 경고와 함께 보여줄 문장. **무엇을 대신 쓰면 되는지** 적음 |
| 메시지 + 에러 여부 | 에러 여부를 참으로 주면 경고가 아니라 **컴파일 에러**가 됨 |

- 메시지가 없는 `Obsolete`는 "쓰지 마라"만 알려주고 대안을 알려주지 않아 불친절함
- 좋은 메시지는 대체할 메서드 이름과 이유를 함께 적음

## 붙일 수 있는 곳

- 클래스, 구조체, 인터페이스, 메서드, 생성자, 프로퍼티, 필드, 이벤트, 열거형 멤버 등 거의 모든 선언

## 알아둘 동작

**컴파일 시점에만 작동함**

- 런타임에는 아무 영향이 없음. 표시된 코드도 정상적으로 실행됨
- 리플렉션처럼 이름 문자열로 호출하는 경우는 컴파일러가 알 수 없어 경고가 뜨지 않음

**Obsolete 코드 안에서는 경고가 나지 않음**

- 이미 `Obsolete`로 표시된 메서드 안에서 다른 `Obsolete` 코드를 쓰면 경고가 나지 않음
- 함께 퇴출될 코드끼리 서로 쓰는 것은 문제 삼지 않기 때문임

**경고를 무시하는 습관 주의**

- 경고가 수십 개 쌓이면 아무도 보지 않게 되어 표시의 의미가 사라짐
- 경고 단계는 짧게 두고, 정리가 끝나면 에러로 격상하거나 삭제하는 것이 좋음

## 게임 개발 관점에서

**유니티 업데이트 때 자주 만남**

- 유니티 버전을 올리면 예전 API에 `Obsolete` 경고가 대량으로 뜨는 경우가 많음
- 메시지에 대체 API가 적혀 있으니 그대로 따라 바꾸면 됨
- 일부는 유니티가 자동으로 코드를 바꿔주겠냐고 묻기도 함 (API 업데이터)

**리팩토링 도구로 활용**

- 직접 만든 메서드를 다른 방식으로 바꾸고 싶을 때, 예전 메서드에 `Obsolete`를 붙이면 **경고 목록이 곧 고쳐야 할 곳 목록**이 됨
- 한 번에 다 바꾸지 않고 하나씩 옮겨 가다가, 경고가 0이 되면 예전 메서드를 지우면 됨

**직렬화 필드 이름을 바꿀 때는 다른 도구**

- 인스펙터에 저장된 필드의 이름을 바꾸면 저장된 값이 사라짐
- 이 경우는 `Obsolete`가 아니라 **예전 이름을 알려주는 별도 어트리뷰트**를 써서 값을 이어받게 함. [[Serialization]] 참고

## 의문점 / 더 알아볼 것

- 최신 .NET에서 추가된 경고 ID 지정, 문서 링크 지정 기능
- 경고를 특정 구간에서만 끄는 방법과 그 위험성
- 경고를 에러로 취급하는 프로젝트 설정
- 유니티 API 업데이터가 동작하는 방식
- 직렬화 필드 이름 변경 시 쓰는 어트리뷰트
