# 메모리 (Memory\<T>)

## 핵심 개념

- **`Memory<T>`**: [[Span]]처럼 **연속된 메모리의 일부를 가리키는** 타입이지만, **힙에 저장할 수 있는** 버전
- Span은 `ref struct`라서 클래스 필드, `async` 메서드, 컬렉션 안에 둘 수 없음
- `Memory<T>`는 일반 구조체라 이런 곳에 자유롭게 둘 수 있음
- 실제 데이터 처리는 Span이 빠르므로, **보관·전달은 Memory로, 처리는 Span으로** 나눠 쓰는 것이 기본 사용법임

## Span과의 비교

| 구분 | `Span<T>` | `Memory<T>` |
| --- | --- | --- |
| 종류 | `ref struct` | 일반 구조체 |
| 저장 위치 | 스택만 | 스택, 힙 모두 |
| 클래스 필드 | 불가 | 가능 |
| `async` 메서드에서 `await`를 넘어서 사용 | 불가 | 가능 |
| 람다 캡처 | 불가 | 가능 |
| 스택 메모리(`stackalloc`) 가리키기 | 가능 | **불가** |
| 요소 접근 속도 | 빠름 | Span으로 꺼낸 뒤 접근 |

- Memory가 스택 메모리를 가리킬 수 없는 이유는, 힙에 저장될 수 있기 때문임. 스택이 사라진 뒤에도 Memory가 남아 있으면 잘못된 위치를 가리키게 됨
- Span의 제약 전체는 [[Span]] 참고

## 쓰는 흐름

```mermaid
graph LR
    A["버퍼의 일부를<br/>Memory로 보관"] --> B["await 등으로<br/>시간이 흐름"]
    B --> C["필요한 시점에<br/>Span으로 꺼냄"]
    C --> D["Span으로 빠르게 처리"]
```

- Memory에서 Span을 꺼내는 데 약간의 비용이 있음. 반복문 안에서 매번 꺼내지 말고 한 번 꺼내서 씀
- 메서드 설계 기준
  - **동기**로 바로 처리하는 메서드는 매개변수를 **Span**으로 받음
  - **비동기**이거나 받아서 보관해야 하는 메서드는 **Memory**로 받음

## ReadOnlyMemory\<T>

- 읽기 전용 버전. 데이터를 바꾸지 않고 넘길 때 씀
- 문자열의 일부를 힙에 보관해 두고 싶을 때도 이것을 씀

## 소유권 문제

- Memory는 메모리를 **빌려서 보고 있는 것**이지, 메모리를 소유하는 것이 아님
- 배열 풀에서 빌린 버퍼를 Memory로 넘겨 놓고, 원래 주인이 그 버퍼를 풀에 **돌려준 뒤에도** Memory로 접근하면, 이미 다른 곳에서 쓰는 메모리를 건드리게 됨
- 에러가 나지 않고 데이터가 조용히 꼬이는 위험한 버그가 됨

**소유권 규칙**

- 메모리를 **소유하는 쪽은 하나**로 정함. 해제(풀 반환)는 소유자만 함
- 소유자가 해제한 뒤에는 그 메모리를 가리키던 Memory를 더 쓰면 안 됨
- 소유권을 명시하는 도구로 메모리 소유자 인터페이스와 메모리 풀이 있음. 소유자는 다 쓰면 반드시 해제함. [[IDisposable & Dispose]] 참고

## 다른 방식과의 비교

| 방식 | 특징 |
| --- | --- |
| 부분 배열을 새로 복사 | 단순하지만 할당과 복사가 생김 |
| 배열 + 시작 + 개수를 따로 전달 | 할당은 없지만 번거롭고 실수하기 쉬움 |
| `ArraySegment<T>` | Span 이전의 대안. 힙에 둘 수 있지만 배열만 가리킴 |
| `Memory<T>` | 배열·문자열 등을 가리키고 힙에 둘 수 있음. Span과 연계됨 |

## 게임 개발 관점에서

**비동기 입출력의 버퍼**

- 파일이나 네트워크를 비동기로 읽을 때, 스트림이 Memory를 받는 메서드를 제공함
- 버퍼 하나를 미리 만들어 두고 그 일부를 Memory로 넘기면, 읽을 때마다 새 배열을 만들지 않아도 됨. [[Byte Stream]], [[Sync & Async]] 참고

**네트워크 수신 처리**

- 받은 데이터 덩어리에서 패킷 하나 분량을 Memory로 잘라 처리 대기열에 넣어두고, 나중에 처리할 때 Span으로 꺼내 해석할 수 있음
- 이때 원본 버퍼를 재사용하기 전에 처리가 끝났는지가 중요함. 소유권 문제와 같은 이야기임

**유니티에서의 범위**

- Span과 마찬가지로 비교적 최근 유니티 버전부터 쓸 수 있음
- 대부분의 게임 로직에서는 필요 없고, 입출력·네트워크처럼 버퍼를 다루는 영역에서 할당을 줄일 때 쓸모가 있음

## 의문점 / 더 알아볼 것
