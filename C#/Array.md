# 배열 (Array)

## 핵심 개념

- **배열**: 같은 타입의 요소들을 **연속된 메모리**에 **고정된 개수**만큼 담는 자료구조
- 인덱스(0부터 시작)로 원하는 위치에 **바로** 접근할 수 있음. 위치 계산이 `시작 주소 + 인덱스 × 요소 크기` 한 번이면 끝나기 때문임
- C#의 배열은 **참조 타입**임. `int[]`처럼 요소가 값 타입이어도 배열 자체는 항상 힙에 있음. [[Dynamic Allocation]] 참고

## 특징

| 특징 | 내용 |
| --- | --- |
| 길이 고정 | 만든 뒤에는 크기를 바꿀 수 없음 |
| 기본값 초기화 | 만들면 모든 요소가 기본값으로 채워짐 (`0`, `false`, `null`) |
| 경계 검사 | 범위 밖 인덱스에 접근하면 `IndexOutOfRangeException` |
| 참조 타입 | 다른 변수에 대입하면 **같은 배열을 공유**함 |

**크기를 바꾸는 것처럼 보이는 경우**

- 크기를 바꾸는 메서드는 실제로 **새 배열을 만들고 내용을 복사**한 뒤 바꿔 끼우는 것임
- 자주 하면 할당과 복사가 반복되므로, 크기가 변하는 데이터는 `List<T>`가 맞음

**대입은 복사가 아님**

- 배열을 다른 변수에 대입하면 두 변수가 같은 배열을 가리킴. 한쪽을 바꾸면 다른 쪽도 바뀜
- 별도의 배열이 필요하면 복사 메서드로 새로 만들어야 함
- 복사도 **얕은 복사**임. 참조 타입 배열이라면 요소가 가리키는 객체는 공유됨

## 값 타입 배열과 참조 타입 배열

```
값 타입 배열 (Vector3[])
┌──────┬──────┬──────┬──────┐
│ 값 0 │ 값 1 │ 값 2 │ 값 3 │   요소 자체가 연속으로 붙어 있음
└──────┴──────┴──────┴──────┘

참조 타입 배열 (Enemy[])
┌──────┬──────┬──────┬──────┐
│ 주소 │ 주소 │ 주소 │ 주소 │   주소만 연속으로 붙어 있음
└──┬───┴──┬───┴──┬───┴──┬───┘
   ▼      ▼      ▼      ▼
  객체   객체   객체   객체      실제 객체는 힙 여기저기에 흩어짐
```

- 값 타입 배열은 순회할 때 메모리를 **순서대로** 읽어서 CPU 캐시를 잘 활용함
- 참조 타입 배열은 요소마다 다른 위치로 건너뛰어야 해서 상대적으로 느림
- 대량의 데이터를 빠르게 처리해야 하는 곳에서 구조체 배열을 쓰는 이유가 이것임

## 다차원 배열과 가변 배열

| 구분 | 다차원 배열 `[,]` | 가변 배열 `[][]` |
| --- | --- | --- |
| 구조 | 하나의 직사각형 덩어리 | 배열을 담은 배열 |
| 행 길이 | 모두 같음 | 행마다 다를 수 있음 |
| 메모리 | 한 덩어리로 연속 | 행마다 따로 할당 |
| 접근 속도 | 일반적으로 가변 배열보다 느린 편 | 일반적으로 빠른 편 |

- 2차원 데이터를 **1차원 배열 하나**에 담고 `y × 가로 + x`로 위치를 계산하는 방식도 많이 씀. 메모리가 연속이라 빠르고, 할당도 한 번뿐임

## 배열과 List

| 구분 | 배열 | `List<T>` |
| --- | --- | --- |
| 크기 | 고정 | 가변 |
| 내부 구조 | 배열 자체 | **내부에 배열을 들고 있음** |
| 추가 | 불가 | 가능. 공간이 모자라면 더 큰 배열로 옮겨 담음 |
| 적합한 경우 | 크기가 정해져 있음, 성능이 중요함 | 크기가 변함 |

- `List`는 공간이 모자라면 보통 **두 배 크기의 새 배열을 만들어 복사**함
- 최종 개수를 대략 안다면 처음에 용량을 지정해 두면 재할당이 줄어듦

## 게임 개발 관점에서

**배열을 반환하는 API는 매번 할당함**

- 컴포넌트 목록, 레이캐스트 결과처럼 배열을 반환하는 유니티 API는 **호출할 때마다 새 배열**을 만듦
- 특히 메시의 정점 목록은 **접근할 때마다 전체 배열의 복사본**을 돌려줌. 반복문 안에서 매번 꺼내 쓰면 정점 수만큼 복사가 반복됨
- 한 번 받아서 지역 변수에 담아 쓰거나, 결과 버퍼를 넘기는 방식의 API를 쓸 것. [[Cast & Overlap]] 참고

**인스펙터에 노출됨**

- 배열과 `List`는 유니티 직렬화 대상이라 인스펙터에서 편집할 수 있음. [[Serialization]] 참고

**빈 배열도 할당임**

- 길이 0인 배열을 반환할 때마다 새로 만들면 그것도 할당임
- 미리 만들어 둔 빈 배열을 재사용하는 표준 방법이 있음

**타일 그리드와 맵 데이터**

- 타일 맵 같은 격자 데이터는 2차원 배열이나 1차원 배열로 표현함
- 크기가 고정이고 위치로 바로 접근해야 하는 데이터라 배열이 잘 맞음

**Job System에서는 다른 배열을 씀**

- 병렬 작업에서는 GC가 관리하지 않는 `NativeArray`를 씀. 반드시 직접 해제해야 함. [[IDisposable & Dispose]] 참고

## 의문점 / 더 알아볼 것

- 배열 공변성 — 문자열 배열을 `object` 배열 변수에 담을 수 있지만, 다른 타입을 넣으면 실행 중 예외가 나는 이유
- `Span<T>` — 배열의 일부를 복사 없이 다루는 방법
- `ArrayPool<T>` — 배열을 빌려 쓰고 돌려주는 풀
- CPU 캐시와 지역성 — 연속된 메모리가 빠른 이유
- 배열 순회 시 경계 검사를 JIT가 제거하는 조건
