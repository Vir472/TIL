# 캐스트와 오버랩 (Cast & Overlap)

## 핵심 개념

- 둘 다 **물리 질의(Physics Query)**임. 물리 시뮬레이션을 기다리지 않고, 코드에서 "지금 여기 뭐 있어?"를 직접 물어보는 기능
- 차이는 **묻는 질문이 다르다**는 것임

| 구분 | Overlap | Cast |
| --- | --- | --- |
| 질문 | 지금 이 자리에 무엇이 겹쳐 있는가 | 이 도형을 이 방향으로 밀면 무엇에 처음 닿는가 |
| 성격 | 정지된 순간의 검사 | 이동 경로 전체를 쓸어내는 검사 |
| 반환 | `Collider2D` (누구인가) | `RaycastHit2D` (누구에게, 어디서, 어떻게) |
| 알 수 있는 것 | 겹친 대상 | 대상 + 충돌 지점, 법선, 거리 |

```
Overlap — 지금 이 자리
        ┌─────┐
        │  ●  │   이 영역 안에 걸치는 것 전부
        └─────┘

Cast — 이 방향으로 밀었을 때
        ●  ─  ─  ─  ─  ─▶ ■
       출발             처음 닿은 지점
       (도형이 지나가는 띠 전체가 검사 범위)
```

## 종류

| 도형 | Overlap | Cast |
| --- | --- | --- |
| 점 | `OverlapPoint` | `Raycast` (크기 0인 캐스트) |
| 원 | `OverlapCircle` | `CircleCast` |
| 사각형 | `OverlapBox`, `OverlapArea` | `BoxCast` |
| 캡슐 | `OverlapCapsule` | `CapsuleCast` |
| 콜라이더 형태 그대로 | `Collider2D.Overlap` | `Collider2D.Cast`, `Rigidbody2D.Cast` |

- **Raycast는 Cast의 특수한 경우**임. 두께가 0인 점을 밀어내는 것
- 도형에 두께가 있으면 레이캐스트가 빠져나가는 틈새(두 타일 사이 등)도 잡아냄
- Cast는 도형이 지나가는 띠를 검사하는 것이라 [[Minkowski Sum & Difference]]에서 다룬 스윕 볼륨과 같은 원리임

## 결과 개수에 따른 변형

| 형태 | 반환 | 비고 |
| --- | --- | --- |
| 기본 (`CircleCast`) | 가장 먼저 닿은 하나 | 대부분 이것으로 충분함 |
| `All` (`CircleCastAll`) | 전부를 배열로 | **호출할 때마다 배열 할당** |
| 결과 버퍼를 받는 오버로드 | 미리 만든 배열이나 리스트에 채움 | 매 프레임 쓰는 곳에 적합 |

- `All` 계열은 [[GC]] 부담이 있으므로 매 프레임 호출하는 코드에서는 버퍼를 받는 쪽을 쓸 것
- 구버전 유니티는 `NonAlloc` 이름의 메서드가 같은 역할을 했음

## RaycastHit2D가 담는 정보

| 멤버 | 내용 |
| --- | --- |
| `collider` | 닿은 대상. 아무것도 안 닿았으면 null |
| `point` | 충돌 지점의 월드 좌표 |
| `normal` | 충돌면의 법선 |
| `distance` | 출발점에서 닿은 곳까지의 거리 |
| `fraction` | 전체 검사 거리 중 몇 % 지점에서 닿았는가 |
| `centroid` | 닿은 순간 도형의 중심 위치 (도형 캐스트일 때) |

- 구조체라서 아무것도 안 닿아도 **값은 반환됨**. 반드시 `collider`가 null인지로 결과 유무를 판단할 것
- `centroid`는 "이 위치까지는 갈 수 있다"를 뜻해서, 캐릭터를 벽 바로 앞까지 이동시킬 때 유용함

## 자주 걸리는 함정

**1. 자기 자신이 잡힘**

- 플레이어 위치에서 Overlap이나 Cast를 하면 **플레이어 자신의 콜라이더**가 결과에 들어옴
- 특히 2D는 기본 설정상 **출발 지점에서 이미 겹친 콜라이더도 감지함** (`Physics2D.queriesStartInColliders` 기본값 true). 거리 0으로 바로 반환됨
- 3D는 반대로 출발 지점 안의 콜라이더를 기본적으로 감지하지 않음. 2D와 3D의 동작이 다르다는 점 주의
- 해결 — [[LayerMask]]로 자기 레이어를 빼는 것이 가장 깔끔함

**2. 트리거까지 잡힘**

- 기본 설정상 질의가 트리거 콜라이더도 감지함 (`Physics2D.queriesHitTriggers`)
- 아이템 획득 범위나 체크포인트 같은 트리거 영역을 땅으로 인식하는 버그가 생김
- 레이어로 분리하거나, `ContactFilter2D`에서 트리거 포함 여부를 지정할 것

**3. 거리를 지정하지 않음**

- Cast 계열은 거리 기본값이 무한대임. 맵 끝까지 검사하게 됨
- 필요한 만큼만(발밑 0.1, 앞쪽 0.5 등) 지정할 것. 정확도와 성능 모두 좋아짐

**4. 시작 위치 기준임**

- Cast는 "지금 위치에서 출발했을 때"를 검사함. 이번 프레임에 이미 이동한 뒤라면 결과가 어긋남
- 이동하기 **전에** 검사하고, 결과를 보고 이동량을 정하는 순서가 맞음

## 게임 개발 관점에서

**언제 무엇을 쓰나**

| 상황 | 선택 | 이유 |
| --- | --- | --- |
| 바닥에 서 있나 (예/아니오만) | Overlap | 발밑 작은 원이 겹치는지만 보면 됨 |
| 바닥의 경사, 바닥까지 거리 | Cast | 법선과 거리가 필요함 |
| 근접 공격 범위 | Overlap | 휘두른 순간 범위 안의 적 전부 |
| 폭발 범위 | Overlap | 반경 안 전부 |
| 이동하면 벽에 박히나 | Cast | 이동 경로를 미리 검사 |
| 빠른 투사체의 관통 방지 | Cast | 프레임 사이 이동 구간 전체 검사 |
| 시야, 조준선 | Raycast | 가로막는 것이 있는가 |
| 스폰 전 빈자리 확인 | Overlap | 그 자리에 뭔가 있는지만 보면 됨 |

**바닥 판정의 두 방식**

- Overlap은 단순하고 안정적이지만 "벽에 닿은 것"과 "바닥에 선 것"을 구분하지 못함
- Cast는 `normal`로 위를 향한 면인지 확인할 수 있음. 경사 위에서 미끄러짐 처리, 바닥에 딱 붙이기에도 쓰임
- [[Collider2D & Collision2D]]에서 다룬 법선 기반 착지 판정과 같은 원리를, 충돌 이벤트를 기다리지 않고 직접 묻는 방식임

**충돌 콜백과의 차이**

- `OnCollisionEnter2D`는 **이미 부딪힌 뒤**에 알려줌. 물리 엔진이 정한 시점에 호출됨
- 질의는 **내가 원하는 시점에, 부딪히기 전에** 물어볼 수 있음
- 그래서 직접 이동을 제어하는 캐릭터(키네마틱)는 콜백보다 질의에 의존하는 경우가 많음

**디버그 시각화**

- 질의는 눈에 보이지 않아서 "왜 안 잡히지"를 추적하기 어려움
- `OnDrawGizmos`로 검사 도형과 거리를 씬 뷰에 그려두면 조정이 훨씬 빨라짐

## 의문점 / 더 알아볼 것

- `ContactFilter2D` — 레이어, 트리거, 법선 각도 범위로 결과를 거르는 방법
- `Rigidbody2D.Cast`와 `Physics2D.BoxCast`의 차이 — 콜라이더 형태를 그대로 쓰는 경우의 이점
- `Physics2D.queriesStartInColliders`를 끄면 다른 기능에 미치는 영향
- `Linecast` — 두 점 사이를 검사하는 방식과 Raycast와의 쓰임 차이
- 키네마틱 캐릭터 컨트롤러가 Cast로 이동을 처리하는 방식 (충돌 후 미끄러짐, 계단 오르기)
- 질의 결과가 같은 프레임의 물리 시뮬레이션 전후 어느 상태를 기준으로 하는가
