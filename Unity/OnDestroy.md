# OnDestroy (OnDestroy)

## 핵심 개념

- **OnDestroy**: 컴포넌트나 게임 오브젝트가 **파괴되기 직전에** 유니티가 자동으로 호출하는 생명주기 메서드
- 오브젝트의 생애에서 **마지막으로 한 번만** 불림
- 짝은 **Awake**임. Awake에서 준비한 것을 OnDestroy에서 정리함
- 바로 앞에 OnDisable이 먼저 호출됨 (켜져 있던 경우)

## 호출되는 시점

| 상황 | 호출 여부 |
| --- | --- |
| `Destroy(gameObject)` 또는 `Destroy(컴포넌트)` | 호출됨 |
| 부모 오브젝트가 파괴됨 | 자식의 컴포넌트도 전부 호출됨 |
| 씬이 언로드됨 (다른 씬으로 전환) | 호출됨 |
| 게임 종료 | 호출됨 |
| 한 번도 활성화된 적 없는 오브젝트가 파괴됨 | **호출되지 않음** |

- Awake가 불린 적 없는 오브젝트는 OnDestroy도 불리지 않음. 처음부터 꺼진 채로 씬에 있던 오브젝트가 대표적임 주의

```mermaid
graph LR
    A["Destroy 호출"] --> W["현재 프레임 처리 계속"]
    W --> D["OnDisable"]
    D --> X["OnDestroy"]
    X --> R["실제 제거"]
```

## Destroy는 즉시 지우지 않음

- `Destroy`를 호출해도 그 자리에서 사라지지 않고, **현재 프레임의 업데이트가 끝난 뒤** 실제로 파괴됨
- 그래서 Destroy 호출 바로 다음 줄에서도 오브젝트에 접근할 수 있음
- 지연 시간을 넘겨 몇 초 뒤에 파괴되게 할 수도 있음
- `DestroyImmediate`는 즉시 파괴하지만, 에디터 스크립트용이며 게임 코드에서는 쓰지 않는 것이 원칙임. [[Instantiate & Destroy]] 참고

## 파괴된 뒤의 참조 — 가짜 null

- 파괴된 오브젝트를 가리키던 C# 변수는 **실제로 null이 되지 않음**. 껍데기 객체는 남고, 유니티 쪽 본체만 사라짐
- 유니티는 `==` 비교를 재정의해서, 파괴된 오브젝트를 null과 비교하면 **true**를 돌려줌
- 하지만 `?.`, `??` 연산자는 이 재정의를 거치지 않아 **파괴된 오브젝트를 살아있다고 판단**함 주의
- 유니티 오브젝트의 null 검사는 `==` 비교나 bool 변환으로 하는 것이 안전함

## 주로 하는 일

**Awake·Start에서 시작한 것 정리**

- Awake나 Start에서 구독한 이벤트는 OnDestroy에서 해제함
- 특히 **정적 이벤트나 싱글톤의 이벤트**를 구독했다면 해제가 필수임. 안 하면 파괴된 오브젝트를 이벤트가 계속 붙잡아 누수가 생김. [[Memory leak]] 참고

**직접 만든 자원 해제**

| 자원 | 이유 |
| --- | --- |
| `renderer.material`로 생긴 머티리얼 복제본 | 오브젝트가 파괴돼도 자동으로 지워지지 않음 |
| 코드로 생성한 텍스처, 메시 | 같은 이유 |
| 네이티브 컨테이너, 파일·네트워크 핸들 | 직접 해제하지 않으면 남음. [[IDisposable & Dispose]] 참고 |

## 주의할 점

**게임 종료·씬 전환 때도 불림**

- OnDestroy는 "적이 죽었다"는 뜻이 아님. 씬을 넘기거나 게임을 끌 때도 똑같이 불림
- 아이템 드롭, 폭발 이펙트 생성 같은 **게임플레이 로직을 OnDestroy에 넣으면**, 씬 전환 때마다 아이템이 쏟아지는 버그가 생김
- 이런 로직은 사망 처리 메서드에서 직접 호출하고, OnDestroy는 정리만 맡김

**종료 중 싱글톤 접근**

- 게임 종료 시 여러 오브젝트가 순서 없이 파괴되므로, OnDestroy에서 싱글톤에 접근하면 이미 파괴되어 있을 수 있음
- "없으면 새로 만든다" 방식의 싱글톤이라면 종료 도중 **새 오브젝트가 생성되어** 정리되지 않은 오브젝트 경고가 뜸. [[Singleton Pattern]] 참고

**오브젝트 간 호출 순서는 보장되지 않음**

- 같은 프레임에 파괴되는 오브젝트끼리 누가 먼저인지 알 수 없음. 서로를 참조하는 정리 로직은 위험함

## OnDisable과의 구분

| 구분 | OnDisable | OnDestroy |
| --- | --- | --- |
| 호출 횟수 | 꺼질 때마다 여러 번 | 파괴될 때 한 번 |
| 짝 | OnEnable | Awake |
| 적합한 일 | 켜져 있는 동안만 필요한 것의 정리 | 생애 전체에 걸친 자원의 해제 |
| 꺼진 오브젝트 파괴 시 | 호출 안 됨 | Awake가 불렸었다면 호출됨 |

- [[OnDisable]] 참고

## 게임 개발 관점에서

**풀링을 쓰면 거의 불리지 않음**

- 오브젝트 풀링에서는 파괴 대신 비활성화로 재사용하므로, OnDestroy는 씬 종료 때나 불림
- 풀링 대상의 정리 로직은 OnDisable에 두고, OnDestroy에는 풀 자체가 사라질 때의 정리만 남김. [[ObjectPooling]] 참고

**씬을 넘어 유지되는 오브젝트**

- 씬 전환에도 파괴되지 않게 지정한 오브젝트는 게임 종료 때 한 번만 OnDestroy가 불림
- 이런 오브젝트가 다른 씬의 오브젝트 이벤트를 구독했다면, 그 씬이 언로드될 때 구독 쪽이 아니라 **발행 쪽에서 정리**되는지 확인해야 함

## 의문점 / 더 알아볼 것

- 유니티의 `==` 재정의 방식과 성능 비용
- Destroy가 실제로 처리되는 프레임 내 정확한 위치
- 게임 종료 시 OnApplicationQuit, OnDisable, OnDestroy의 순서
- 모바일에서 앱이 강제 종료될 때 OnDestroy가 보장되는가
- 관련 노트 — [[Unity Lifecycle]], [[Event & Pub-Sub Pattern]]
